Flash the membership reader from a Raspberry Pi

A step-by-step guide starting with an unflashed ESP32-WROOM-32E development board and ending with a live MQTT status message.

Verified in this session: Python 3.13.5, PlatformIO Core 6.2.0, a successful firmware build and upload, and an online:true MQTT heartbeat. Physical RC522 card reading has not yet been tested.

1. Prepare the Pi and board

You need a Raspberry Pi with a Terminal, an internet connection for tool downloads, this SmartShop repository, an ESP32 development board, and a USB data cable. A cable that only provides power cannot upload firmware.

The silver module on the tested board reads ESP32-WROOM-32E. The project uses PlatformIO's esp32dev board target. That target successfully built and uploaded in this session. Other board variants may require a different target or GPIO mapping.

Connect the ESP32 to the Pi by USB. The RC522 does not need to be connected for flashing or MQTT verification. Open Terminal and run these commands separately:

python3 --version
command -v pio
ls /dev/ttyUSB* /dev/ttyACM*

The tested Pi reported Python 3.13.5 and /dev/ttyUSB0. No output from command -v pio means PlatformIO is not on the current PATH. A missing /dev/ttyACM* is fine if a USB serial device is listed.

If multiple devices are listed, compare the list with the ESP32 unplugged and plugged in. Use its actual port in subsequent commands; /dev/ttyUSB0 is the example verified here.

This guide assumes the repository is at ~/Projects/smartshop. Adjust that path if your copy is elsewhere.

2. Install PlatformIO

PlatformIO compiles the code and transfers it to the ESP32. Install it in a dedicated Python environment. Run each command separately and stop if a command fails:

sudo apt update
sudo apt install -y python3-venv
python3 -m venv ~/platformio-venv
source ~/platformio-venv/bin/activate
python -m pip install --upgrade platformio
pio --version

The verified result was:

PlatformIO Core, version 6.2.0

Your prompt should now include (platformio-venv). In every new terminal where you need pio, activate this environment again:

source ~/platformio-venv/bin/activate

Installation reference: PlatformIO installation using pip.

3. Check the MQTT broker

MQTT carries messages between the ESP32 and SmartShop. A broker, such as Mosquitto, must already be installed and running on the Pi. This session reused an existing broker; a new broker installation was not tested.

Inspect the running service and its configuration:

sudo systemctl status mosquitto --no-pager
sudo grep -RnE '^[[:space:]]*(listener|allow_anonymous|password_file|acl_file|include_dir)\b' /etc/mosquitto

The existing broker used these settings:

include_dir /etc/mosquitto/conf.d
listener 1883 0.0.0.0
allow_anonymous true

listener 1883 0.0.0.0 listens on the Pi's IPv4 interfaces. allow_anonymous true permits clients without a username or password, so the tested firmware used empty MQTT credentials.

This anonymous, unencrypted setup is for an initial test on a trusted LAN. Do not expose port 1883 to the internet. An authenticated broker requires an existing broker account; entering a password in the firmware does not create that account. This firmware uses plain MQTT, so changing the port alone does not enable TLS.

If Mosquitto is absent, inactive, or configured differently, resolve the broker setup before continuing. Do not overwrite an existing broker configuration just to match this example.

Find the Pi's network addresses:

hostname -I

Use the Pi's LAN address reachable from the ESP32's Wi-Fi network. If multiple addresses appear, select the address for that network. The ESP32 must not use localhost: on the ESP32, that would refer to itself.

4. Configure firmware settings

Go to the dedicated membership firmware folder. Copy the example without overwriting any existing local settings, then open the local file:

cd ~/Projects/smartshop/firmware/esp32/membershipReader
cp -n secrets.example.h secrets.h
nano secrets.h

For the anonymous broker configuration above, use the following structure. Replace the three placeholder values with your own Wi-Fi credentials and Pi LAN address. Keep the quotation marks.

#pragma once
#define WIFI_SSID "YOUR_WIFI_SSID"
#define WIFI_PASSWORD "YOUR_WIFI_PASSWORD"
#define MQTT_HOST "YOUR_PI_LAN_IP"
#define MQTT_PORT 1883
#define MQTT_USER ""
#define MQTT_PASSWORD ""
#define MEMBERSHIP_TOPIC "SmartShop/membership"
#define NTP_HOST "pool.ntp.org"
SettingMeaning
WIFI_SSIDThe Wi-Fi network name the ESP32 will join.
WIFI_PASSWORDThat Wi-Fi network's password.
MQTT_HOSTThe Pi's LAN IP address, as a quoted string.
MQTT_PORT1883, without quotation marks, for this broker's plain MQTT listener.
MQTT_USER / MQTT_PASSWORDBoth empty strings for the tested anonymous broker. For an authenticated broker, use its configured account credentials, which are separate from your Pi login.
MEMBERSHIP_TOPICKeep SmartShop/membership; the backend and monitoring commands must use the same prefix.
NTP_HOSTA reachable time server. The firmware needs synchronized time before it will accept scan commands.

In nano, save with Ctrl+O, press Enter, then exit with Ctrl+X. Keep secrets.h local and uncommitted. Do not publish its contents.

5. Build the firmware

From the membershipReader directory, with the PlatformIO environment activated:

pio run

The first build downloads the ESP32 toolchain and required libraries, so it may take several minutes. This project pins the following dependencies in platformio.ini:

  • Target: esp32dev; framework: Arduino.
  • ESP32 platform: espressif32@6.12.0.
  • MFRC522 1.4.12, PubSubClient 2.8, ArduinoJson 7.4.2.

A successful build ends with output similar to:

Successfully created esp32 image.
... [SUCCESS] ...

This only creates the firmware image on the Pi. It has not yet changed the code running on the ESP32.

6. Upload to the ESP32

Keep the board connected by USB. Close any serial monitor using its port, then run:

pio run -t upload --upload-port /dev/ttyUSB0

If it remains at Connecting..., hold the board's BOOT button until uploading begins, then release it.

The verified upload ended with:

Hash of data verified.
Leaving...
Hard resetting via RTS pin...
... [SUCCESS] ...

The firmware is now stored on the ESP32. It starts after the upload reset and will run again whenever the board receives power. It does not require PlatformIO to remain open.

If you change secrets.h later, repeat the upload command to compile and install the new settings.

7. Verify MQTT communication

On the Pi, subscribe to the reader's status topic:

mosquitto_sub -h localhost -p 1883 \
  -t 'SmartShop/membership/status' -v

Here, localhost is correct because this command runs on the Pi where the broker is running.

If the command is missing, install the MQTT client tools, then retry:

sudo apt install -y mosquitto-clients

Within a few seconds, expect a message similar to this, repeating about every five seconds:

SmartShop/membership/status {"v":1,"online":true,"reader_epoch":"..."}

The actual reader_epoch is a randomly generated connection identifier. It changes when the reader reconnects; do not configure or copy it into your settings.

Wait about 15 seconds, then press Ctrl+C to stop the subscriber. Stopping it does not stop the ESP32 or broker.

Success: a live online:true message confirms the ESP32 is running, joined Wi-Fi, and reached the MQTT broker. It does not establish that the RC522 can read a card or that NTP time synchronization has completed.

Optional serial monitor

pio device monitor --port /dev/ttyUSB0 --baud 115200

Exit the PlatformIO serial monitor with Ctrl+C. The firmware reports Wi-Fi connection status, its local IP, the MQTT destination, and failed MQTT connection state codes. Press the board's EN/reset button while monitoring to see startup messages again. It prints Armed: remove any card, then present a card. after accepting a scan command, and UID: ... after reading a card.

8. Next step: connect the RC522

Not yet physically verified in this session. The following wiring matches the firmware. Unplug USB power before connecting or changing wires.

RC522 pinESP32 connection
VCC / 3.3V3V3 (3.3 V)
GNDGND
RSTGPIO 4
SDA / SSGPIO 5
SCKGPIO 18
MISOGPIO 19
MOSIGPIO 23
IRQLeave unconnected

Use GPIO numbers, not header positions. Check your board's labels. Supply the RC522 with 3.3 V, not 5 V/VIN, and share GND. The RC522's SDA pin is SPI chip select in this setup.

Inspect all connections before reconnecting USB. A card will only be read after a backend command arms the reader. A card already resting on the reader must be removed and presented again after arming; the scan window is 60 seconds.

Continue with the membership diagnostic in the repository hardware setup guide (a Markdown file). Run the diagnostic with the SmartShop app stopped, then compare its UID with the ESP32 serial output. Enrollment is a later, separate check.

Troubleshooting

SymptomWhat to check
pio: command not foundRun source ~/platformio-venv/bin/activate in this terminal.
No USB serial deviceCheck the USB data cable and connection; compare port listings before and after plugging in the board.
Upload says port is busyClose serial monitors and other programs using the port.
Upload says permission deniedCheck ls -l /dev/ttyUSB0 and groups. On a Pi where the device belongs to dialout, add your user with sudo usermod -aG dialout "$USER", then log out and back in. Reactivate the PlatformIO environment afterward.
Upload remains at ConnectingHold BOOT until writing begins, then release it. Confirm the correct board and port.
MQTT subscriber says connection refusedCheck that Mosquitto is running and listening on port 1883.
No status messagesCheck Wi-Fi credentials, the Pi's LAN address, network reachability, broker access rules, and the exact topic prefix. Ensure you uploaded after changing settings.
Serial monitor is quietAfter a successful connection it can be quiet until arming. Press EN/reset to see startup diagnostics, and use MQTT status messages to check connectivity.
Online but will not arm or readPhysical reading is a separate test. Check backend commands, topic permissions, NTP access, wiring, and removal/re-presentation after arming.
